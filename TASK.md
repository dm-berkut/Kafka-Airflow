# Задачи

Создать **Kafka Producer** и **Kafka Consumer** для загрузки, получения и обработки данных, а также автоматизировать их запуск с помощью **Apache Airflow**.

## 1. Источник данных

В PostgreSQL в базе данных **`kafka_task`**, в схеме **`kafka_prod`** находится таблица **`events_source`**, в которую ежедневно поступают данные о действиях пользователей на сайте.

Данные могут быть некорректными:

- лишние пробелы;
- неправильный регистр;
- некорректные email;
- ошибочные даты;
- неверный возраст и т.д.

### Структура таблицы `events_source`

| Поле | Тип | Описание |
|------|-----|----------|
| id | BIGSERIAL | Уникальный идентификатор записи |
| user_name | TEXT | Имя пользователя |
| email | TEXT | Электронная почта пользователя |
| age | TEXT | Возраст пользователя |
| site_action | TEXT | Действие пользователя на сайте |
| event_date | TEXT | Дата и время события |

---

## 2. Создать Kafka Topic

Создать Kafka Topic для хранения данных из таблицы.

Название:

```text
task_events_log_<фамилия>
```

Например:

```text
task_events_log_berkut
```

---

## 3. Разработать Kafka Producer

Необходимо написать **Kafka Producer** (используя библиотеку **confluent-kafka** или **Spark** по согласованию с лидом), который:

- подключается к PostgreSQL;
- получает новые записи из таблицы `events_source`;
- отправляет их в Kafka Topic.

---

## 4. Разработать Kafka Consumer

Необходимо написать **Kafka Consumer** (используя библиотеку **confluent-kafka** или **Spark** по согласованию с лидом), который:

- получает сообщения из Kafka Topic;
- выполняет очистку и валидацию данных;
- записывает корректные данные в новую таблицу.

### Целевая таблица

База данных:

```text
kafka_task
```

Схема:

```text
kafka_dev
```

Название таблицы:

```text
events_log_<фамилия>
```

Например:

```text
events_log_berkut
```

---

# Правила обработки данных

## Поле `user_name`

Требования:

- не должно быть пустым;
- не должно состоять только из пробелов;
- длина менее 100 символов;
- привести к единому формату:
  - каждое слово начинается с заглавной буквы;
  - остальные буквы — строчные.

Пример:

```text
"   иВАН   ИВАНОВ " → "Иван Иванов"
```

---

## Поле `email`

Требования:

- привести к нижнему регистру;
- проверить корректность email;
- если значение отсутствует или некорректно — записать `NULL`.

Пример:

```text
IVAN@MAIL.RU
↓
ivan@mail.ru
```

---

## Поле `age`

Требования:

- привести к числовому типу;
- допустимый диапазон:

```text
1–100
```

Если значение выходит за пределы диапазона или не является числом:

```text
age = 0
```

---

## Поле `site_action`

Поле обязательно.

Допустимые значения:

- login
- logout
- view
- click
- purchase

Если значение отсутствует или отличается от списка — запись не загружается.

---

## Поле `event_date`

Требования:

- не должно быть пустым;
- привести к типу `TIMESTAMP`;
- привести к единому формату даты.

Если дата отсутствует или не может быть преобразована — запись не загружается.
